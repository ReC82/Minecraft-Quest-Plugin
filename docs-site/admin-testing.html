Outils admin de test

Implémentation : command.QuestCommand (sous-commande admin), quest.YamlQuestEngine#reload / #validate, quest.progress.QuestProgressEngine#resetQuest / #resetAllQuests, database.QuestProgressRepository#deleteQuest / #deleteAllForPlayer. Cette page couvre le rechargement des définitions, la consultation et la réinitialisation de la progression de quêtes d'un joueur — voir Quêtes pour le format des quêtes elles-mêmes.

Correction récente : les messages de confirmation de /quest admin reset (et les autres messages de quête — acceptation, abandon, complétion, journal graphique) affichaient parfois les balises MiniMessage du titre de la quête littéralement (ex. Quête <gold>Premiers pas</gold> réinitialisée au lieu d'un titre coloré). Corrigé : le titre s'affiche désormais toujours formaté normalement.

Recharger les définitions — /quest admin reload

Permission rpgquest.admin.

  • Relit tous les fichiers de plugins/RPGQuest/quests/*.yml depuis le disque et remplace l'ensemble de quêtes actif — à chaud, sans redémarrage.
  • Recharge aussi messages.yml dans la même commande (les deux sont rechargés ensemble, jamais séparément).
  • Reconstruit les écouteurs d'objectifs (BREAK_BLOCK, KILL_ENTITY...) en fonction des types réellement utilisés par les quêtes rechargées.
  • N'affecte jamais les dialogues (plugins/RPGQuest/dialogues/*.yml) — aucune commande ne les recharge à chaud, voir Dialogues ; un dialogue modifié exige un redémarrage complet du serveur.
  • La progression déjà en cours des joueurs n'est jamais perdue par un reload (elle vit dans la base de données, pas dans les définitions).
/quest admin reload

Réponse : Rechargement : <N> quête(s) chargée(s), <N> erreur(s)., suivie d'une ligne par erreur (fichier + message) s'il y en a.

Valider sans appliquer — /quest admin validate

Permission rpgquest.admin.

  • Relit et valide les mêmes fichiers YAML que reload, avec le même rapport d'erreurs — mais en dry-run : l'ensemble de quêtes actif n'est jamais remplacé.
  • Utile pour vérifier qu'un nouveau fichier de quête est syntaxiquement correct avant de l'appliquer avec reload, sans risquer de casser les quêtes déjà actives sur le serveur en production.
  • Ne touche ni messages.yml, ni les écouteurs d'objectifs, ni rien d'autre — uniquement un rapport.
/quest admin validate

Même format de réponse que reload (compte de quêtes + erreurs), sans jamais rien appliquer.

Consulter l'état d'un joueur

Trois commandes en lecture seule, aucune n'altère la progression.

CommandePermissionEffet
/quest list rpgquest.quest Liste toutes les quêtes connues (y compris NOT_STARTED) et leur état pour soi-même.
/quest progress [id] rpgquest.quest Sans argument : uniquement les quêtes déjà commencées (état ≠ NOT_STARTED). Avec un id : détail objectif par objectif (current/total) de l'étape en cours ; vide si la quête n'est pas active en mémoire.
/quests — Journal graphique (menu paginé) — même information que /quest list, présentation en inventaire.

Ces trois commandes s'exécutent toujours pour le joueur qui tape la commande — il n'existe pas de variante « admin » en lecture pour consulter un autre joueur ; connectez-vous en tant que ce joueur (ou demandez-lui) pour vérifier le résultat d'un reset.

Réinitialiser une quête — /quest admin reset <joueur> <id>

Permission rpgquest.admin. Cible un joueur en ligne uniquement (comme /skills admin, /backpack admin...).

  • Supprime totalement la ligne d'état persisté (quest_progress) de cette quête pour ce joueur — pas de remise à NOT_STARTED, la ligne disparaît.
  • Supprime tous ses compteurs d'objectifs persistés (quest_objective_progress) pour cette quête.
  • Retire aussi la progression en mémoire si la quête était active — un événement de jeu juste après le reset ne la fait pas repartir d'où elle en était.
  • Permet de recommencer la quête, même si repeatable: false : le blocage de /quest accept ne porte que sur une ligne COMPLETED existante, qui n'existe plus après le reset.
  • Ne touche ni à l'inventaire, ni à l'économie (portefeuille, transactions), ni à aucune autre quête du joueur.
# Exemple exact : réinitialiser rpgquest:premiers_pas pour LoDyMcFly
/quest admin reset LoDyMcFly premiers_pas
# équivalent explicite (avec namespace) :
/quest admin reset LoDyMcFly rpgquest:premiers_pas

Réponse attendue à l'admin : Quête Premiers pas réinitialisée pour LoDyMcFly. LoDyMcFly reçoit aussi un message l'informant du reset. Vérifiez ensuite avec /quest list (sur le compte LoDyMcFly) que rpgquest:premiers_pas est repassée à NOT_STARTED, puis /quest accept premiers_pas pour confirmer qu'elle redevient acceptable.

Réinitialiser toutes les quêtes — /quest admin reset <joueur> all

Même permission, même contrainte (joueur en ligne).

  • Remet toutes les quêtes du joueur à NOT_STARTED (suppression de toutes ses lignes quest_progress) en une seule opération.
  • Supprime tous ses compteurs d'objectifs, pour toutes les quêtes.
  • Vide aussi tout le cache mémoire de progression du joueur.
  • Ne touche à aucune autre donnée joueur : profil, variables, inventaire, économie, backpacks, claims, compétences RPG (progression/XP) — uniquement les tables quest_progress et quest_objective_progress.
# Exemple exact : tout réinitialiser pour LoDyMcFly
/quest admin reset LoDyMcFly all

Réponse attendue à l'admin : Toutes les quêtes de LoDyMcFly ont été réinitialisées. Vérifiez avec /quest list (LoDyMcFly) que toutes les quêtes affichent NOT_STARTED.

Checklist manuelle (exemple LoDyMcFly / premiers_pas)

  1. /quest admin validate — vérifier 0 erreur(s) sur les quêtes livrées avec le plugin.
  2. Modifier légèrement un champ d'une quête existante (ex. title), puis /quest admin reload — vérifier que le changement apparaît immédiatement dans /quest list, sans redémarrage.
  3. LoDyMcFly connecté, exécute /quest list — noter l'état actuel de rpgquest:premiers_pas.
  4. Si elle n'est pas active : /quest accept premiers_pas (un Title « Quête commencée » doit apparaître), puis parler au Guide pour progresser d'un cran.
  5. /quest progress premiers_pas (LoDyMcFly) — vérifier que l'objectif en cours affiche un compteur > 0.
  6. Depuis un compte admin : /quest admin reset LoDyMcFly premiers_pas — vérifier le message de confirmation des deux côtés.
  7. /quest list (LoDyMcFly) — rpgquest:premiers_pas doit être revenue à NOT_STARTED.
  8. /quest progress premiers_pas (LoDyMcFly) — doit maintenant être vide (plus aucune progression active).
  9. /quest accept premiers_pas (LoDyMcFly) — doit réussir même si la quête était COMPLETED et non-répétable avant le reset.
  10. Vérifier que l'inventaire, le solde (/money) et les autres quêtes de LoDyMcFly n'ont pas bougé pendant toute l'opération.
  11. Optionnel — tout réinitialiser d'un coup : /quest admin reset LoDyMcFly all, puis /quest list (LoDyMcFly) pour confirmer que toutes les quêtes sont à NOT_STARTED.
