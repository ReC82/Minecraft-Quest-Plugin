## Analyse

Audit avant codage (limité à ce qui permettait de décider, comme demandé) :

- **`waypoint.WaypointService`** (issue #124, déjà en place) : repères physiques partagés,
  découverte individuelle par joueur persistée (`waypoint_discoveries`), rendu versionné
  (`WaypointModelRegistry`/`WaypointModelV1` — support `COBBLESTONE_WALL` + `GOLD_BLOCK` +
  `STONE_BUTTON`). Ne faisait que de la **génération + découverte**, aucune notion de voyage/menu.
  Deux méthodes manquaient pour servir de base en lecture seule au nouveau système : « waypoints
  actifs découverts par ce joueur » et « ce waypoint est-il encore activement découvert ? » —
  ajoutées (`discoveredBy`, `hasActivelyDiscovered`), aucune autre modification de ce service.
- **`waystone.WaystoneService`** : réseau de voyage sur grille fixe avec retour au Hub, système
  **distinct et non touché** — le cahier des charges interdit explicitement toute fusion
  d'identité/table entre waypoint/waystone/borne, respecté strictement (aucun import croisé de
  modèle, tables séparées).
- **GUI existante** : `ui.QuestJournalService`/`QuestJournalListener`/`JournalInventoryHolder`
  fournissent le patron exact à reproduire — `InventoryHolder` marqueur dédié, annulation
  systématique de tout clic/drag dans l'inventaire concerné (anti-vol/duplication), session par
  joueur tenue côté serveur, fermeture qui nettoie la session. Repris à l'identique pour
  `BeaconMenuHolder`/`TravelBeaconListener`/`BeaconMenuSession`.
- **Téléportation sûre** : `travel.RandomSafeLocationFinder#findAtColumn` (déjà utilisé par la
  génération de waypoints elle-même) réutilisé tel quel pour l'arrivée près d'un waypoint ciblé —
  aucune nouvelle logique de recherche de sol sûr écrite.
- **Claims** : `claim.ClaimService#mainClaimOf` identifié comme point d'entrée pour une future
  catégorie « Mon claim » (#151) — **non câblé** dans cette session (hors périmètre annoncé).
- **Recherche graphique** : aucun précédent dans le dépôt (aucune utilisation antérieure
  d'`InventoryType.ANVIL`). Confirmé après audit que Paper/Bukkit permet de créer une enclume
  **virtuelle** (`Bukkit.createInventory(holder, InventoryType.ANVIL, titre)`, sans bloc réel dans
  le monde) et d'y lire le texte tapé via `AnvilInventory#getRenameText()` sur
  `PrepareAnvilEvent` — méthodes dépréciées (marquées pour suppression future par Paper) mais
  **fonctionnelles et compilables** sur la version ciblée ; choix assumé faute d'alternative plus
  simple dans le temps imparti, à revoir si Paper les supprime réellement.
- **Schéma** : nouvelle table `travel_beacons` (migration V19, `SchemaMigrator.CURRENT_VERSION`
  18→19) — jamais une colonne ajoutée aux tables `waypoints`/`waystones` existantes.

## Travail effectué

**Modèle et persistance** :
- `travel.beacon.model.TravelBeacon` (nouveau record, même esprit que `Waypoint` mais table/paquet
  séparés).
- `database.TravelBeaconRepository` (nouveau, JDBC pur).
- `SchemaMigrator` : migration V19 (`travel_beacons`), version courante 18→19.

**Service métier** (`travel.beacon.TravelBeaconService`, nouveau, `PluginService`) :
- Placement administrateur idempotent (`placeAt`) : pose la structure (support waypoint +
  `DIAMOND_BLOCK` + `OAK_BUTTON`) à la position réelle de l'admin, orientée selon son regard ;
  refuse une deuxième borne à la même colonne (vérifié **avant** tout nouveau calcul de hauteur de
  sol — sinon la structure fraîchement posée aurait faussé le recalcul à l'appel suivant, bug
  trouvé et corrigé pendant les tests).
- Interaction bouton → ouverture du menu racine (3 catégories), jamais de découverte de waypoint
  déclenchée par la borne elle-même.
- Menu « Waypoints découverts » : liste **strictement** les waypoints actifs du joueur courant
  (jamais ceux d'un autre joueur), pagination 45/écran, navigation, recherche.
- Recherche graphique par enclume virtuelle : coût de réparation forcé à 0 à chaque
  `PrepareAnvilEvent` (aucun coût XP), texte lu puis l'objet jamais réellement donné (clic sur le
  résultat toujours annulé). Normalisation casse + accents (`Normalizer` NFD).
- Sélection d'un waypoint : revalidation stricte (`WaypointService#hasActivelyDiscovered`) puis
  arrivée sûre (`RandomSafeLocationFinder#findAtColumn`) ; monde non chargé / colonne dangereuse /
  waypoint supprimé-désactivé-non découvert → message clair, aucune téléportation.
- Protection des blocs de la borne : `TravelBeaconProtectionListener` (casse, explosion, piston,
  feu, fluide, entités — même couverture que `WaypointProtectionListener`, dupliquée
  volontairement pour garder les deux systèmes indépendants).
- Catégories « Mon claim » / « Villages » : affichées dans le menu racine, clic → message explicite
  « pas encore disponible dans cette version (issue #151) » — jamais un bouton silencieux.

**Commande admin** : `/rpgadmin travel beacon set` (permission `rpgquest.admin.world`, même patron
que `/rpgadmin spawn set` — position réelle de l'exécutant, jamais de coordonnée inventée).

**Câblage** (`bootstrap.RPGQuestBootstrap`) : construction de `TravelBeaconRepository`/
`TravelBeaconService`, écouteurs (bouton/menu + protection) enregistrés, service passé à
`RpgAdminCommand`.

## Tests automatiques

`TravelBeaconServiceTest` (nouveau, 9 cas, `MockBukkit` + vraie base SQLite temporaire, découverte
simulée via le **vrai bus d'événements Bukkit** — `TravelBeaconServiceTest` est dans un paquet
différent de `waypoint`, donc jamais d'appel direct à ses méthodes de paquet) :

- placement d'une borne → structure exacte (diamant + bouton bois) + idempotence (refus à la même
  colonne) ;
- casse d'un bloc de borne sans bypass → bloquée ;
- clic sur le bouton → ouverture du menu racine ;
- menu « Waypoints » sans aucune découverte → état vide affiché ;
- découvertes isolées entre deux joueurs ;
- **parcours complet** : découverte dans le Wild → menu → sélection → retour sûr tout près du même
  waypoint ;
- clic périmé / destination inconnue → aucune téléportation, aucun crash ;
- pagination au-delà de 45 entrées (46 waypoints découverts, 45 puis 1) ;
- recherche insensible à la casse et aux accents (`normalize`).

Deux bugs trouvés et corrigés **pendant** l'écriture des tests (pas seulement après coup) :
1. Décalage d'ancre d'un bloc dans `placeAt` (copié-collé depuis un calcul différent de celui de
   `WaypointService`), qui faisait systématiquement échouer le placement dès qu'un sol explicite
   était préparé.
2. Idempotence de `placeAt` cassée par le recalcul de hauteur de sol **après** qu'une première
   structure ait déjà été posée (la colonne devient alors plus haute) — corrigé en vérifiant
   l'existence d'une borne à la colonne **avant** tout nouveau calcul de hauteur.

**Résultats** : `:test` ciblé sur `travel.beacon.*`, `waypoint.*`, `SchemaMigratorTest`,
`RpgAdminTestShortcutsCommandTest` → **tous verts**. Suite complète du module racine (`:test`)
lancée en tâche de fond pour confirmer l'absence de régression ailleurs — voir la mise à jour ci-
dessous si le résultat est arrivé avant l'envoi de ce rapport, sinon se référer au commit suivant
