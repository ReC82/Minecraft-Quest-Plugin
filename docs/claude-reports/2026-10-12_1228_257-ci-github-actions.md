### Tests ciblés — `scripts/dev/check.sh`

Modules touchés depuis l'amont (ou `--base`, `--module`, `--full`), `--tests` pour une classe,
`bash -n` sur les scripts modifiés. **Mémoire de ce qui est validé** : marqueur indexé par
l'empreinte Git du **code** du module (arbres de ses dossiers + build commun) — un commit de
documentation ne l'invalide pas, un commit du panel n'invalide pas le plugin, un code non commité
n'est jamais « validé ». Mesuré : un cycle ciblé (`--module panel --tests '*AgentStoreTest'`) prend
**15 s**.

### Validation adaptée au déploiement — `scripts/lib/validation.sh`

`val::head_ci` part de HEAD et remonte **tant que le commit n'a aucun run CI et n'est que de la
documentation**, sans jamais franchir un commit de code. `val::ci_status` lit le **run** du workflow
« CI » ; sans `gh`, sans réseau ou sans run, la réponse est « none » — jamais « vert ».

| Run CI du commit | Panel (`deploy.sh`) | Plugin (`deploy-verygames.sh`) |
|---|---|---|
| vert | aucun test, `installDist` | aucun test, `assemble` depuis l'arbre propre |
| rouge | **refus**, sauf `--allow-ci-red` (tracé) | **refus**, sauf `--allow-ci-red` |
| en cours | `--wait-ci` (30 min max), sinon comme absent | idem |
| absent | marqueur local, sinon `:control-panel:test` | marqueur local, sinon `:test` |

`deploy.sh` refuse désormais un code de panel non commité (`--allow-dirty` pour forcer), fonctionne
sous `sudo` (`safe.directory`), et écrit `/opt/plugadmin/app/DEPLOYED` (commit, branche, date,
preuve de validation). `deploy-verygames.sh` affiche la ligne « validation : … » dans son
récapitulatif, et `--local-validation` force le rejeu local.

### Deux défauts trouvés en route, et corrigés

1. **Mon propre défaut de conception.** La première version de `val::ci_status` lisait le check
   « CI OK », qui n'existe qu'une fois ses dépendances terminées : un run en cours paraissait
   « absent ». Et la première `ci_commit` renvoyait au dernier commit de **code**, alors que la CI ne
   tourne que sur le commit **poussé en tête** — donc sur un commit sans run. Constaté contre le vrai
   GitHub, corrigé (`5a87218`), couvert par 28 assertions.
2. **Un vrai bogue du panel, révélé par la première CI.** `BuildingSitesPageTest` a échoué en CI et
   jamais en local : `agent_action.created_at` est **à la seconde**, et deux relevés de la même
   seconde se départageaient au hasard — l'ancien pouvait passer pour le dernier. La machine AWS,
   plus lente, ne tombait jamais dans la même seconde. Tri secondaire sur `rowid` dans les cinq
   lectures ordonnées (`ac88238`) ; test de régression **prouvé** (il échoue sans le correctif).
   Exactement l'intérêt d'une CI sur une machine différente.
