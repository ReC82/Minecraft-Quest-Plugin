## Analyse
- Le filet `ClaimWorldSafetyListener` observait déjà (MONITOR) les `/tp` internes à Claims et traçait
  l'arrivée dans le claim d'autrui sans la refuser (comportement validé à l'étape 2 avant décision).
- `/claim admin tp` et `/rpgadmin world tp` téléportaient sur la seule permission `rpgquest.admin.world`
  (défaut OP).
- La téléportation de diagnostic PlugAdmin (`ClaimAdminTeleport`, #637) déplace aussi un administrateur
  vers un claim précis (cause PLUGIN) : sans adaptation, elle aurait été annulée par D2 avec un message
  générique « refusée par une autre règle ».
- `TeleportCause` de l'API Paper actuelle : COMMAND, PLUGIN, SPECTATE, UNKNOWN, ENDER_PEARL,
  CONSUMABLE_EFFECT (ex-chorus), DISMOUNT, EXIT_BED, portails.

## Travail effectué
- **D2** — `ClaimWorldSafetyListener#onDirectTeleportIntoClaim` (priorité HIGH, `ignoreCancelled`) :
  annule une téléportation COMMAND / PLUGIN / SPECTATE, **depuis n'importe quel monde**, dont la
  destination est dans un claim que `ClaimVisitPolicy` n'ouvre pas au joueur téléporté ; message clair
  au joueur ; log `[claims-safety] téléportation (…) de … REFUSÉE`. Permis : propriétaire et membres,
  session bypass active (`rpgquest.bypass.claimworld` via `AdminBypassMode.allows`), `/tp` à l'intérieur
  du claim où le joueur se trouve déjà (entré à pied : rien n'est gagné), destination hors claim,
  déplacements de gameplay, cause `UNKNOWN` (non identifiable → tracée seulement, point laissé ouvert).
- Nouvelle interface `claim.ClaimVisitPolicy` (`MEMBERS_ONLY` = `Claim#isTrusted`) : point d'extension
  pour un futur système d'amis, injectable dans le listener (constructeur de test/variante complète).
- **D1** — nouvelle classe `claim.ClaimAdminTeleportGate` (`permits` + message commun) appliquée à
  `/claim admin tp <joueur>` (`ClaimCommand`, qui reçoit désormais `AdminBypassMode`) et à
  `/rpgadmin world tp <monde des claims>` (`RpgAdminCommand#handleWorldTp`). Aide de `/claim admin tp`
  complétée « mode bypass actif requis ». `/claim admin sendhome` (Jo) et `world tp` vers un autre
  monde inchangés.
- `ClaimAdminTeleport` (#637) : après le contrôle d'éligibilité, refus `REFUSED` explicite (« activez
  /rpgadmin bypass on ») vers le claim d'un autre joueur sans bypass, avant tout déplacement.
- Revue sécurité (manuelle) : aucun nœud de bypass lu hors `AdminBypassMode` (garde
  `BypassOnlyThroughAdminModeTest` verte) ; les téléportations PLUGIN internes du plugin ne visent pas un
  claim d'autrui (renvoi Hub, Jo → son propre claim, portail CLAIM_HOME → son claim) ; aucun piège :
  le refus laisse le joueur à sa position d'origine, le filet anti-blocage est inchangé. Effet assumé :
  une balise/waystone située dans le claim d'autrui n'est plus atteignable par téléportation directe.
- Déploiement DEV (voir plus bas), docs, TC-436 étapes 6-8, registre.
